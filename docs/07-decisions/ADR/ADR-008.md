# ADR-008 多工程仓库与独立 Go module 根

日期2026-11-20；Accepted。用户明确修订Go不能放仓库根，后续还有CLI、Agent、前端等工程。本决定覆盖ADR-001首切片中关于根目录Go工程位置的旧约定，其只读/授权/功能范围保持。

原设计：根go.mod、cmd/hostsec、internal及根Go lint配置，按单一Go产品布局。问题：仓库根与module根混为一体，后续前端、分发集成和独立程序缺少工程边界；脚本与CI也默认root cwd。

决定：backend/go.mod为唯一当前Go module，路径github.com/bingooyong/AIHostSecurityInspector/backend，独立cmd程序共用internal领域内核；frontend、integrations、deploy等在规划中有职责归属，实际落地任务启动前不制造空实现。Go工程工具源码也在backend/tools，根scripts只有跨工程脚本。根Makefile、Schema、示例、文档和Trellis是仓库级职责。当前不需要go.work、多个Go module或DI依赖。

影响：现有Go源码与imports、fixture路径、构建/lint/漏洞/SBOM cwd、GitHub CI toolchain/cache路径、Trellis config和当前任务交付路径都必须同步。现有CLI命令、flags、JSON、退出码和build产物位置不变。现无对外模块消费者或发布；以后子目录module发布按Go官方tag约定。历史V1文件、bootstrap原始证据不改写，当前文档更新并链接迁移说明。

权衡：单Go module减少依赖与版本漂移，不代表所有程序链接同样依赖。特权Collector通过包依赖边界/独立binary控制，未来需要独立SDK或不兼容版本才再次拆module。常驻hostsec-agent单列后续需求，不混同AI Agent；当前MVP仍是一次性Collector。

验证：迁移前race和11条CLI基线；迁移后逐字输出/退出码对比、单测/race/vet/lint、目录/module边界、CLI Schema、DAG/来源、依赖漏洞/SBOM、双架构构建。实际结果见REPOSITORY-LAYOUT-REPORT，不把设计或交叉构建当运行验收。
