# 安全架构

设计基线 0.1，2026-11-20。文档 IMPLEMENTED，运行控制随对应任务验收，当前首切片不具备远程执行、模型调用或主机扫描能力。

## 1. 信任边界

| 边界 | 不可信输入 | 拒绝/约束 |
|---|---|---|
| CLI/Agent → 应用层 | flags、目标、文件内容、主体声明 | 强类型参数、大小/深度限制、真实主体上下文、按目标授权；拒绝任意命令 |
| 控制端 → SSH/Runner | 远端身份、网络、任务包 | strict host key/mTLS/签名；目标和安全域绑定；失败关闭 |
| 主机 → Collector/规则 | 文件、进程、日志、配置与工具输出 | 字节/记录上限、标准化校验、不可作为指令或代码；权限失败独立状态 |
| 规则包 → 引擎 | YAML、引用、谓词、基线 | 版本/来源/签名、有限操作符、预算、正反例、禁止脚本 |
| 结果包 → 存储 | 压缩包路径、manifest、声明身份 | 解压前限制、拒绝穿越/符号链接/重复对象、哈希及签名校验、隔离导入 |
| 分析视图 → Provider → UI | 敏感字段、Prompt Injection、模型引用 | allowlist 脱敏、无工具调用、严格输出 Schema、同 scan/host 证据验证、报告转义 |

资产配置的 `authorized: true` 在单用户 CLI 仅表示受信任管理员准备的扫描范围；拥有本机写权限者可以编辑清单，不能把它当多租户安全边界。平台阶段所有入口从服务端身份解析权限，Agent 不能自行提交更高权限的主机集合。

## 2. 执行与权限

默认 READ_ONLY。目标主机只允许固定 Collector 和审查过的扫描器查询/读取；不杀进程、删文件、隔离文件、改账号/服务/网络/配置、安装卸载软件。输出目录、审计、SSH 登录日志和读取 atime 等副作用须披露，不能宣称绝对零写入。

固定 Collector 应 root-owned，父目录不允许巡检用户写入；连接使用非 root 账号。必要特权按固定入口、固定 Profile 和字段授权，禁止 `NOPASSWD: ALL`。SSH 不暴露远端 command 字符串、不允许客户端自定义 ProxyCommand/转发；主机密钥变化必须重新登记，禁止自动接受。生产部署由独立变更流程完成。

深扫/IR 执行要求有效审批，而非非空 approval_id。记录绑定计划哈希、具体目标、Profile、路径、限额、执行人、审批人、有效期和窗口；执行前再次验证，过期/撤销/目标变化拒绝。操作者不得批准自己的高敏感任务。

## 3. 证据与真实性

每个对象记录 host_id/scan_id/attempt_id、采集时间、模块与 Collector 版本、状态、完整性和 SHA-256。manifest 固定对象集合；规则求值记录 rule_version。缺采集字节没有可伪造的空成功哈希；失败证据只支撑失败事实，不能支撑被检测属性 PASS。

SHA-256 检测固定对象的变化，不能抵抗攻击者同时重写对象与 manifest，也不能证明失陷内核提供真实数据。Runner 任务与结果采用签名和身份认证；CLI 导出未签名包只具有完整性，不宣称来源可信。跨主机关联拒绝，历史比较需可信基线。原始对象、标准化对象与 AI 视图独立存储和权限。

## 4. AI 与报告

AI 默认关闭。外发前使用允许字段构建新视图，凭据、完整原始日志/argv/环境、文件样本不能外发；禁用配置不能靠环境变量意外启用。模型无工具/网络导航/执行能力，输入中 URL 或指令只作为证据。未知证据 ID、其他 host/scan ID、失败证据支撑成功事实、非法枚举、越界置信度均拒绝整个研判或标记失败。

模型错误不修改确定性 Findings，不升级规则原始严重度，不阻止 JSON/Markdown 报告。报告区分 facts/inferences/unknown/limitations，转义日志、文件名和模型文本，不自动加载其中链接或资源；整改为人工建议。

## 5. 资源与路径保护

计划必须显示总时限、模块时限、并发、最大文件数/单文件大小/总字节、IO 速率、深度、排除挂载和目录。执行器必须真正实施，单纯显示限额不构成保护。禁止默认扫描 `/`、数据库、备份和网络挂载；路径从批准策略引用，解析真实路径并检查位于 allowlist，处理符号链接与采集中路径变化。

资源压力、超时、取消、磁盘不足停止新工作并保留已落盘证据，标记 PARTIAL/FAILED/CANCELLED。不能因上限截断就把未覆盖部分当成无风险。

## 6. 验证门禁

首切片覆盖未知 flag、任意命令 flag、越权目标/混合组、缺授权、恶意 YAML/JSON 和 host key 绕过配置；执行层上线前再做 SSH 认证/指纹、固定命令、sudo/只读差分、取消/资源边界。证据阶段做篡改、跨扫描引用、包穿越与伪造签名；AI 阶段做秘密诱饵、注入文本、无效 JSON/引用和故障降级。每项风险必须有复现、修复和回归证据；设计检查不能写成攻击测试已通过。
