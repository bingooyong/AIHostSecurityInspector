# 部署手册与上线门禁

状态：首切片部署说明为设计基线；Collector/SSH/工具/AI/MCP/Runner/Web 部署均 PLANNED。本轮没有生产主机连接或远程软件安装。运行命令与本轮验证结果以 README 和执行报告为准。

## 1. 当前本地构建边界

控制端需要固定 Go 工具链与批准依赖来源，根make build调度backend模块，可用go -C backend build；程序入口为`backend/cmd/hostsec`。首切片只提供版本、doctor、资产校验/列表、离线计划；样例为文档地址，不能用于真实扫描。macOS 控制端可做离线计划，但 doctor 必须明确 Linux Collector 不可用，不能称已具备本机扫描能力。Linux amd64/arm64 交叉编译只产生构建产物，不是目标运行验收。

不把尚未实现的 scan、report、mcp 或环境变量配置描述为可运行命令；不复制 V1.0 插件中的占位 MCP URL 上线。

## 2. Linux 试点准备（后续门禁）

| 项目 | 必需证据 |
|---|---|
| 授权与范围 | host_id、负责人、OS/version/arch、区域、允许 Profile、非生产授权、明确路径/日志范围 |
| 身份 | 本机身份指纹、登记 IP、严格 known_hosts/host key 的独立核对记录 |
| 账号 | 非 root 巡检账号、独立凭据引用、轮换流程；root 登录与宽泛 sudo 禁止 |
| Collector | 受控构建版本/摘要/签名、root-owned 二进制与不可写父目录、固定入口 |
| 特权 | 最小必要能力与逐模块权限审查，拒绝 `NOPASSWD: ALL`；不足时允许 partial |
| 性能 | 并发、时限、IO/CPU/RSS/磁盘预算和基准；deep/IR 维护窗口与审批 |
| 数据 | 证据本地目录权限、留存/备份、脱敏与是否允许外发审批 |

以上真实企业信息尚未提供，阻止远程/生产验收，不阻止离线开发。先隔离测试 VM/容器，覆盖至少一个实际 Linux x86_64 与 ARM64 运行环境，再做非关键测试试点、UAT，生产另走变更审批。

## 3. 外部工具安装与离线

安装/卸载不属于 scan。批准构建区固定工具、内容包、依赖、许可证、SHA-256 和签名后，通过企业软件分发独立安装。目标主机扫描时不访问公网更新。osquery/Lynis P0、OpenSCAP/ClamAV/YARA P1 逐个验收；缺工具/内容过期明确 UNKNOWN，不因离线就下载脚本替代。

每个工具的发行版/架构/版本输出和只读副作用必须测试。Lynis 的日志/报告只写批准目录；ClamAV 不删除/移动/复制命中项、不自动更新签名；OpenSCAP 不 remediation/远程下载；YARA 规则包来源和许可独立审查。

## 4. 模型与平台（后续）

AI 需显式启用、批准 Provider/endpoint/model、凭据引用、TLS 与外发策略；本地模型也不能绕过脱敏。没有外发授权只生成确定性报告。MCP 在协议/鉴权/工具级越权测试完成后部署；区域 Runner 需任务签名、mTLS、信任公钥、有效期/nonce、区域 allowlist、重放防护与证书轮换。中央不直接跨区访问全部主机。

Web/PostgreSQL/对象存储为 WP7 以后部署范围，安全审计角色只读、管理员不自动获得所有主机数据。Kafka/Kubernetes 等只有具体容量需求证明必要后再决策。

## 5. 发布与回滚

发布包包含版本、提交、工具链、平台、SBOM、许可证、二进制 SHA-256、规则/策略/Schema/内容版本与签名。门禁含格式/vet/lint/单元/集成/漏洞/Schema/规则正反例/安全边界/构建产物验证；本地已执行与 CI 配置存在分开报告。

升级前在测试环境验证数据兼容，保留旧二进制和只读数据备份。数据库迁移与 Collector 部署有独立回滚点；回滚不得覆盖已有证据或把新 Schema 结果静默降级。生产变更需用户明确授权，本轮不发布、不推送、不连接生产。
