# 01. 需求规格说明书（PRD）

## 1. 用户角色
| 角色 | 职责 | 权限 |
|---|---|---|
| 平台管理员 | 配置平台、Runner、模型 | 不自动拥有全部主机数据权限 |
| 安全管理员 | 策略、审批、风险管理 | 按授权区域 |
| 安全分析员 | 查看发现、证据、报告 | 不执行主机处置 |
| 运维人员 | 维护主机资产、协助扫描 | 仅授权主机 |
| 主机责任人 | 查看责任主机结果、反馈 | 仅责任主机 |
| 审计人员 | 查看任务、审批、操作日志 | 只读 |
| Agent / MCP Client | 调用受控巡检能力 | 无任意 Shell |

## 2. 业务流程
资产登记 → 选择目标与 Profile → dry-run 计划 → 深度扫描审批 → 只读采集 → 证据保存与哈希 → 标准化 → 规则检测 → 可选 AI 研判 → 报告 → 人工复核 → 整改跟踪 → 复扫对比。

## 3. 功能需求

### 3.1 主机资产
- FR-ASSET-001（P0）：支持 YAML 导入。
- FR-ASSET-002（P0）：稳定 host_id，不以 IP 作为唯一标识。
- FR-ASSET-003（P0）：记录 OS、版本、架构、区域、环境、业务系统、责任人、重要级别。
- FR-ASSET-004（P0）：授权状态、允许 Profile、维护窗口。
- FR-ASSET-005（P1）：标签、分组、批量导入、变更审计。
- FR-ASSET-006（P1）：主机身份漂移检测。

### 3.2 扫描任务
- FR-JOB-001（P0）：quick / standard / deep Profile。
- FR-JOB-002（P0）：dry-run 显示目标、模块、影响和审批要求。
- FR-JOB-003（P0）：并发、超时、取消、重试和失败原因。
- FR-JOB-004（P0）：记录执行人、审批人、策略和版本。
- FR-JOB-005（P0）：工具缺失、权限不足、采集失败明确标记。
- FR-JOB-006（P1）：定时扫描。
- FR-JOB-007（P1）：分区域 Runner。
- FR-JOB-008（P1）：离线任务包导入导出。

### 3.3 数据采集
- FR-COL-001（P0）：OS、内核、架构、启动时间和资源。
- FR-COL-002（P0）：进程、父子关系、运行用户、路径、启动时间和网络关联。
- FR-COL-003（P0）：监听端口、活动连接、路由和本机防火墙。
- FR-COL-004（P0）：用户、组、登录、sudo / 管理员权限、SSH 公钥元数据。
- FR-COL-005（P0）：systemd、cron、启动项和计划任务。
- FR-COL-006（P0）：软件包和服务清单。
- FR-COL-007（P0）：关键目录权限、SUID/SGID 和异常可写目录。
- FR-COL-008（P0）：SSH、审计、防火墙、SELinux / AppArmor。
- FR-COL-009（P1）：osquery。
- FR-COL-010（P1）：ClamAV、YARA、OpenSCAP、Lynis。
- FR-COL-011（P1）：Windows Collector。
- FR-COL-012（P2）：容器和 Kubernetes 节点。

### 3.4 检测规则
- FR-RULE-001（P0）：规则 ID、版本、平台、严重度、逻辑、证据要求和误报说明。
- FR-RULE-002（P0）：进程、网络、账号、持久化、权限、基线。
- FR-RULE-003（P0）：软件版本与本地漏洞情报匹配；情报缺失时说明覆盖不足。
- FR-RULE-004（P0）：规则命中可解释、可追溯。
- FR-RULE-005（P0）：PASS / FAIL / UNKNOWN / NOT_APPLICABLE。
- FR-RULE-006（P1）：自定义规则、测试和灰度。
- FR-RULE-007（P1）：企业允许进程、端口、服务和软件基线。
- FR-RULE-008（P1）：历史差异。

### 3.5 恶意软件排查
- FR-MAL-001（P0）：进程路径、哈希、权限、父进程、网络和启动项关联。
- FR-MAL-002（P0）：识别临时目录执行、可执行文件不存在等信号。
- FR-MAL-003（P1）：ClamAV 只报告，不删除。
- FR-MAL-004（P1）：YARA 规则必须有来源、版本和审查记录。
- FR-MAL-005（P1）：Rootkit 信号需说明能力限制。
- FR-MAL-006（P1）：文件样本外传需单独审批。
- FR-MAL-007（P2）：Wazuh / Velociraptor 集成。

### 3.6 AI 研判
- FR-AI-001（P0）：AI 可选，不影响确定性扫描。
- FR-AI-002（P0）：输入脱敏、摘要化并带 evidence_id。
- FR-AI-003（P0）：结构化输出结论、置信度、理由、证据和建议。
- FR-AI-004（P0）：不得引用不存在证据或声称未执行的检测。
- FR-AI-005（P0）：区分事实、推断、未知和未覆盖。
- FR-AI-006（P0）：不得仅凭单一异常认定木马。
- FR-AI-007（P1）：OpenAI API、兼容接口和本地模型。
- FR-AI-008（P1）：调用成本、耗时和失败率统计。
- FR-AI-009（P1）：人工反馈用于规则优化，不直接自动训练。

### 3.7 报告闭环
- FR-REP-001（P0）：JSON / Markdown。
- FR-REP-002（P0）：范围、时间、版本、完整性、发现项、证据和限制。
- FR-REP-003（P0）：采集不完整不能显示“全部安全”。
- FR-REP-004（P1）：HTML 和风险看板。
- FR-REP-005（P1）：误报、确认、接受风险、整改、修复、复测状态。
- FR-REP-006（P1）：扫描差异。

## 4. 非功能需求
安全：只读默认、最小权限、SSH 指纹校验、无任意命令。
性能：并发、限速、超时、IO 保护。
可靠性：单模块失败不丢失整个任务；支持部分完成。
可扩展：Collector / Rule / Analyzer / Storage / Transport 插拔。
可移植：Linux x86_64 / ARM64 优先，Windows 后续。
审计：任务、审批、模型调用和导出留痕。
数据治理：脱敏、加密、可配置留存。
可观测：结构化日志和任务指标。

## 5. 验收标准
1. 未授权主机扫描成功数为 0。
2. dry-run 完整展示目标和 Profile。
3. quick 扫描生成结构化结果和报告。
4. 每条 finding 引用真实 evidence，或明确标记覆盖不足。
5. AI 不可用时确定性报告仍可交付。
6. deep 无审批时被阻断。
7. 不执行删除、杀进程、改配置等动作。
8. 工具缺失、权限不足、超时均明确标记。
9. 扫描、证据、报告使用同一 scan_id。
