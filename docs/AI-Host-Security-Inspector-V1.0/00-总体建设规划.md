# 00. 总体建设规划

## 1. 项目定位
建设企业内网主机安全巡检与威胁研判平台。它不是传统杀毒软件的替代品，也不是把生产主机 root Shell 交给 AI 的运维工具，而是统一资产、采集、规则、证据、研判和报告的平台。

## 2. 建设目标
- 主机可见性：进程、网络、账号、服务、软件、启动项和关键配置。
- 安全检查：恶意文件、异常进程、异常外联、权限、漏洞和基线偏差。
- 风险研判：关联多条证据，识别组合风险。
- 证据闭环：可追溯、可复核、可复扫、可对比。
- 平台复用：CLI、Codex Skill、MCP、Web 和定时任务共用引擎。

## 3. 工具选型

| 工具 | 定位 | 建议 |
|---|---|---|
| osquery | 结构化主机数据采集 | 首期优先集成 |
| Lynis | Linux 安全审计 | 首期可选 |
| OpenSCAP + SCAP Security Guide | 安全基线 | 兼容发行版上启用 |
| ClamAV | 已知恶意文件特征扫描 | 指定目录、限速、只报告 |
| YARA | 恶意特征规则匹配 | 使用经审查的规则集 |
| Velociraptor | 深度取证、跨主机 Hunt | 异常主机调查时使用 |
| Wazuh | 持续监控、FIM、SCA、漏洞和告警 | 主机规模扩大后评估 |
| Falco | Linux 运行时行为检测 | 第二阶段评估 |

不要自研病毒特征引擎、YARA 匹配、SCAP 评估、漏洞情报库。自研重点是统一编排、证据标准化、规则关联、权限治理、AI 研判和报告。

工具边界：
- osquery 提供数据，不等于自动识别所有木马。
- ClamAV 无命中不等于绝对干净。
- YARA 依赖规则覆盖和质量。
- Lynis / OpenSCAP 主要做配置与基线。
- Velociraptor 更适合深度取证。
- Wazuh 功能完整，但部署运维成本更高。

## 4. 三阶段路线

### Phase 1：CLI 巡检 MVP
Go `hostsec` CLI；主机 YAML 清单；Linux 只读 Collector；SSH 指纹校验；quick / standard / deep；基础规则；JSON / Markdown / HTML 报告；AI Provider；Codex / Claude Skill。

### Phase 2：AI-Agents 托管
任务 API、MCP Server、资产和证据持久化、分区域 Runner、审批、审计、定时任务、模型网关和离线结果包。

### Phase 3：Web 平台
主机资产、任务中心、风险中心、证据详情、规则库、例外管理、RBAC、风险趋势，并按需集成 Wazuh / Velociraptor / Falco。

## 5. 推荐技术栈
- Go：CLI、Collector、Orchestrator、API、MCP。
- OpenSSH：首期远程执行；严格 host key 校验。
- osquery / ClamAV / YARA / OpenSCAP / Lynis：专业检测适配器。
- YAML：资产、策略和规则。
- JSON / JSONL：结果契约。
- SQLite + 本地文件：CLI；PostgreSQL + MinIO：平台化。
- OpenAI-compatible API + 本地模型：统一 Analyzer。
- LangGraph：需要状态恢复和人工审批的复杂流程时再评估；PydanticAI 可用于类型安全的结构化模型调用。

## 6. 关键决策
- D-001：Agent 是入口和研判助手，不是执行内核。
- D-002：Linux 优先，Windows 后续适配。
- D-003：生产主机默认只读。
- D-004：模型不接触原始全量日志。
- D-005：模型故障不影响确定性扫描。
- D-006：隔离网络采用区域 Runner，不让中央平台跨区直连。

## 7. 待决事项
主机 OS / 数量 / 网络区、堡垒机和密钥管理、现有 EDR / SIEM、数据外发审批、AI-Agents 平台 MCP 规范。未确认内容不得写成既定事实。
