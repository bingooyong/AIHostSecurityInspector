# 09. 部署与运维手册

## 1. 部署形态

### CLI 单机
- 在授权工作站或内网 AI-Agent 节点部署 `hostsec`。
- 专用巡检账号访问目标主机。
- 本地保存 SQLite、证据和报告。
- 模型调用走批准出口或本地模型。

### 区域 Runner
- 每个安全域部署独立 Runner。
- Runner 从中央任务服务拉取任务。
- 校验签名、有效期、nonce、目标和 Profile。
- 访问本区域主机。
- 通过 mTLS 回传结果或离线导出。
- 不跨区域共享 SSH 凭据。

### 平台化
建议组件：`hostsec-api`、`hostsec-worker`、`hostsec-mcp`、PostgreSQL、MinIO、Web UI。Redis / NATS 等只有在吞吐和可靠性需求明确后引入。

## 2. 主机端准备
确认 OS / 版本 / 架构；创建专用巡检账号；配置 SSH 公钥和主机指纹；安装固定 Collector（如采用 Agent 模式）；评审特权采集；检查专业工具；确定扫描路径和维护窗口。不得将宽泛 sudoers 配置直接复制到生产。

## 3. 模型配置
通过环境变量或密钥管理服务：
- `HOSTSEC_AI_PROVIDER`
- `HOSTSEC_AI_BASE_URL`
- `HOSTSEC_AI_MODEL`
- `HOSTSEC_AI_API_KEY`

API Key 不得写入仓库、主机清单、扫描结果和报告。

## 4. 离线环境
在联网构建区下载并验证依赖、工具包和规则包；生成摘要和签名；审批后导入内网仓库。隔离区不依赖公网；模型不可用时只执行本地规则；结果包包含 manifest、证据、报告和签名。

## 5. 规则和病毒库更新
规则记录来源、版本、发布日期和 SHA-256；YARA 规则需审查测试；ClamAV 病毒库通过受控镜像或离线包更新；OpenSCAP 内容匹配目标发行版；禁止扫描时从不受信任 URL 下载脚本执行。

## 6. 运维监控
Runner 在线状态、任务成功率、连接失败率、Collector 版本、工具版本和病毒库时间、扫描耗时、CPU / IO、证据存储量、AI 成功率 / 耗时 / 成本、脱敏失败、审批和越权拒绝次数。

## 7. 备份恢复
备份 PostgreSQL、对象存储元数据、规则包、策略包和签名公钥。恢复后验证证据摘要和报告引用关系。API Key 和 SSH 凭据不得随普通业务备份明文保存。

## 8. 升级
CLI / Collector / Rules / Schema 分别版本化；测试环境先验证；灰度 1～2 台非关键主机；生产升级走维护窗口；Schema 向后兼容；规则升级不得触发自动处置。

## 9. 故障处理
- SSH 失败：检查路由、堡垒机、指纹和账号，不自动改用其他地址。
- 权限不足：标记模块未完成，提交权限评审。
- 工具缺失：标记未执行，不伪造结果。
- 磁盘不足：暂停写入并告警，不覆盖历史证据。
- 模型不可用：跳过 AI，生成规则报告。
- 结果包校验失败：隔离，不导入正式结果库。
